# 缓存统计与前缀诊断

界面说明（0.4.2）：桌面面板只展示配置、运行概况与缓存统计，已移除重复摘要、运行周期与重置操作、HMAC 诊断和出站监听区域。下文的诊断与重置说明描述保留的后端接口和内部行为。

本次更新修正统计与增加被动观察。请求变换、身份档案、模型路由、缓存键和断点保持 0.3.6 的行为。诊断相同也不证明上游缓存一定命中；上游 TTL、路由、逐出、服务端重写与隐藏计费规则仍需独立验证。

## 统计口径

- 计数单位是经过本插件模拟路径的 HTTP 生成尝试，不等同于聊天轮数。未配置或 None 供应商仍走原样短路，不纳入统计。
- OpenAI Responses 使用 `input_tokens`，Chat Completions 使用 `prompt_tokens`；分别读取 `input_tokens_details.cached_tokens`、`prompt_tokens_details.cached_tokens`。
- Anthropic 总输入 = `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`。因此命中率分母包含新输入、读缓存及写缓存；SSE 起始与增量用量按字段合并，不用单个最大快照替代。
- 只有明确报告有效读缓存字段的样本进入命中率分母：`sum(cached) / sum(known input)`。写缓存单独累积。缺少读缓存字段是「未报告」，与明确返回 `0` 区分。
- 覆盖率 = 明确报告有效读缓存字段的尝试 / 全部已结算尝试。无 usage、未报告缓存、畸形 / 矛盾用量分别计数；未知样本不按零命中处理。矛盾用量不进入已知命中率。
- HTTP 失败、流错误、取消、未完成分开计数。成功传输但缺少用量仍记成功，并标明用量缺失。结果在响应读完、错误或取消后结算；在途尝试暂未进入结果计数。
- 「首次观测」是插件首次看到此会话 / 模型 / 档案 / 协议 / purpose 组合，不等于上游真实冷缓存。「同轮多次 HTTP」只表示相同宿主请求上下文出现多个出站尝试，可能包含重试，不能据此确认重试原因。
- 会话来源为宿主缺失时标记 fallback。该情况下原有随机会话回退行为保留，诊断可据此识别归组不稳定。

JSON/SSE 观察器仅从协议定义的顶层用量路径提取数据，忽略工具输出等业务字段中的 `usage`。观察器逐块读取响应，有限保留单事件 / 选定 usage 值；4 MiB 后出现的尾部 usage 仍可采集。大事件、超深 JSON 或畸形结构会记录采集无效，原响应字节照常返回。

## 窗口与维度

面板默认最近 20 次完成的 HTTP 尝试，也可查看本次运行累计、最近活动会话，并按模型 / 档案 / 协议 / purpose 组合筛选。这里的「最近活动会话」由最近出站请求确定，不假定等于浏览器当前打开的聊天。

累计在插件重新加载、重启或手动重置时开始新周期；不会导入旧版进程内计数。统计与诊断互相独立：重置某供应商统计不清诊断，清诊断不重置统计。

统计保留最多 128 个供应商，每个供应商 64 个会话维度组合、128 个模型维度组合与 256 个操作标记；分组按有界 LRU 淘汰。供应商累计不随内部维度淘汰而归零，故长时间运行后保留分组之和可能小于累计。最近窗口按响应结算顺序计数；各分组的近期统计从该供应商全局最近 20 次已结算尝试中过滤，不为每个分组单独补足 20 次。

手动重置后，重置前已在途的完成回调不会回填新周期。前台面板约每 5 秒刷新运行数据，后台页面暂停自动刷新；自动刷新只合并 runtime，保留草稿和配置 revision。手动刷新会重新同步完整配置。

## HMAC 前缀诊断

默认启用，最多 100 条诊断、64 个活跃会话基线，每条默认比较最多 2048 条消息。系统指令、工具定义、请求参数、消息历史、缓存键及端点以随机 32 字节运行期密钥生成 HMAC。会话、缓存键和内容指纹分别显示 `s-`、`k-`、`h-` 短标记。不同插件运行期的标记不能交叉比较，密钥不写盘。

内存中只保存指纹、长度、计数、技术枚举和用量，不保存原始消息、系统文本、工具参数 / 结果、原始 session id、缓存键、认证头或端点。HMAC 不发送给上游，也不修改出站内容。诊断与原来的脱敏出站监听分开，监听关闭时仍可采集统计与诊断。

变化类型包含模型、档案、协议、端点、缓存键、系统指令、工具、其他参数、历史改写、仅追加、保持一致以及超出比较范围。可见共同消息前缀条数及首个变化消息序号。保留对象字段顺序以观察实际 JSON 前缀变化。

硬边界包含 4 Mi 字符、131072 节点、64 层及对象键数限制。比较超限、前次基线不完整、基线淘汰或暂停后恢复时，标明不完整 / 首次观测；不会把未比较部分当成相同。

暂停只停止新诊断与基线更新，旧条目保留；清空删除条目及对应基线。开关和清空都只作用于当前运行内存，不写供应商配置，也不修改上游请求。

## 如何分析低命中

1. 先确认采样周期、窗口、模型和会话，并检查覆盖率。覆盖率低时，优先看未报告 / 缺 usage / 无效采集，而非把它们当成低命中。
2. 在同一会话和模型下观察连续几次正常请求。首次观测及请求取消不应直接与已热的连续请求混为同一结论。
3. 对照诊断：系统 / 工具 / 参数变化或历史改写能定位本地前缀扰动；仅追加表示已观测前缀保持，但不保证上游命中。
4. 只有获得这些证据后，再评估请求优化或向上游验证 TTL / 路由。本版本没有增加 `24h` 保留、模型专属缓存参数、固定新模板或路由重写。
