# DSH 客户端模拟插件

给 DeepSeek Harness（DSH）加一个左侧栏面板：选中一个**已配置供应商**、选一个要模拟的客户端（**Claude Code / Codex / None**），点保存即生效。之后在原对话框里用该供应商的模型发消息，插件会在出站请求上同时改写**请求头**和**请求体**指纹。

- **一次只模拟一个供应商**：保存新的供应商时，原来那个自动恢复为不模拟。
- **不改官方配置**：插件用自己的设置命名空间，不写 `llm-pi-ai` 等官方适配器的内部配置。
- **官方供应商不列**：`llm-deepseek*` 适配器（DeepSeek 官方 / 官方账号）本身不需要伪装，面板里不显示。
- **保存即生效**：未保存的更改保留在当前面板；保存后用于后续请求，面板明确显示「未保存 / 已生效」。
- **缓存统计**：按供应商、会话、模型 / 身份模板查看本次运行累计与最近 20 次 HTTP 尝试；兼容三种协议的读缓存与写缓存用量，明确区分上游未报告、有效零命中、失败及取消。桌面双栏面板集中显示设置、运行概况与缓存指标。
- **按供应商并发上限**：可为每个供应商设置同时在途的生成请求数（0 = 不限制，1–64），超出后可选「排队等待」或「直接拒绝」（拒绝时新请求立刻报错，并行子代理不会被创建）。面板实时显示 active / limit 与排队数。

## 0.4.2 更新说明

本次相对 0.3.6 的更新，汇总缓存观测升级、受限高度下的滚动修复与桌面单屏布局整合。

**更新原因**

- 原有缓存数据只按供应商累计，部分协议的缓存字段与输入分母处理不完整，未报告字段容易与零命中混淆。
- 主面板受宿主固定高度裁切，底部内容不易到达；统计与调试区堆叠后，常用设置需要反复滚动查看。

**更新内容与优化**

- 统一 Anthropic Messages、OpenAI Responses、Chat Completions 的 JSON/SSE 用量解析，区分有效零命中、字段未知、用量异常、失败、取消和未完成；新增缓存字段覆盖率与写缓存统计。
- 支持最近 20 次 HTTP、本次运行累计与指定会话统计，按模型、身份档案、协议筛选；前台每 5 秒刷新运行数据，同时保留未保存的表单内容。
- 增加有界、仅在内存保留的 HMAC 前缀诊断，辅助定位系统指令、工具、参数和消息历史变化；保留后端接口。
- 将设置置于左栏，运行概况和缓存指标集中在右栏；移除顶部重复缓存摘要、底部运行时间与重置区、前缀诊断及出站监听区，常用桌面窗口一屏显示完整。
- 主面板使用独立的溢出容器，窄屏时自动纵向排列并保留滚动访问；设置页嵌入面板继续使用宿主滚动。
- 流式统计随调用方逐块读取，保留取消和背压行为，支持采集较长响应末尾的 usage；已到达协议终点的正常流不再误记为取消。

**验证结果**

- TypeScript 检查通过，离线契约与集成测试 **288/288** 通过。
- 单屏组件交互检查 **13/13** 通过；1366×768、1280×720、1024×768、1280×660 桌面视口均验证无需纵向滚动，窄屏和暗色布局已检查。
- 已在实际 DSH 页面验证 0.4.2 布局，并核对更新前后供应商配置一致。

本次改进统计准确性和页面使用体验，未调整请求指纹、身份模板、缓存键、缓存保留时间、断点或上游路由；不以观察到的命中率变化作为上游缓存效果提升的承诺。

## 安装

环境：Node.js **22.17.0+**。本工程验证于 DSH LLM/settings/webServer `0.2.2-rc.5`、Cordis `4.1.0`。

### 方式一：安装打包好的 tgz（推荐）

从 [Releases](https://github.com/SquareDance166123/dsh-mimic/releases/latest) 下载 `dsh-mimic-0.4.2.tgz`，打开 DSH **插件 → 添加插件 → 安装现有插件**，包来源填 tgz 的**完整绝对路径**：

```text
<下载目录>/dsh-mimic-0.4.2.tgz
```

装好后到左侧栏点「客户端模拟」即可。若宿主提示需要重启，重启**正在使用的那个 DSH 实例**（另开一个服务器不会更新原有 GUI）。

### 方式二：从源码构建

```bash
pnpm install --ignore-scripts
pnpm run typecheck
pnpm test
pnpm run build
pnpm pack --pack-destination ./release
```

运行时依赖只有 `schemastery 3.19.0` 与 `cosmokit 1.9.0`。

## 使用

1. 在 DSH 原有「模型 / 供应商」设置里配置好供应商与模型。
2. 打开左侧栏「客户端模拟」，在「供应商」中选中目标供应商（列表只含第三方、已配置的供应商）。
3. 在「客户端身份」中选 `Claude Code` 或 `Codex`；保持原请求时选「原样请求」。
4. 在「并发上限」中填写该供应商同时在途的生成请求数（`0` = 不限制，范围 1–64），并选择「超限排队」或「超限报错」。
5. 点「保存更改」。顶部「当前模拟」显示供应商、客户端和并发上限，右侧同步展示运行概况及缓存指标。

## 模拟内容

- **Claude Code**：`User-Agent`（`claude-cli/<version> (external, cli)`）、`X-Stainless-*`、`Anthropic-Beta`、`X-App`、会话/请求标识；请求体 `system[0]` 计费归因块、`system[1]` 客户端标识、`cache_control` 断点、`metadata.user_id`（`user_<hex>_account_<uuid>_session_<uuid>`），以及结构性工具名映射。版本、Stainless runtime 版本、计费块 `cc_version` 必须同版本，任一漂移都会被网关识别。
- **Codex**：`originator` / `User-Agent`（`codex_*`）、`session-id` / `thread-id` / `x-client-request-id` / `x-codex-beta-features` / `x-codex-window-id` 等头，以及 `instructions`（约 20K 字符的系统提示词，每次请求都带、可整体替换）。
- **日期隐写擦除**：真实 Claude Code 在非官方 base URL 下会把日期信息以隐写方式嵌入 system prompt，作为「是否经过代理」的信标，插件会对这段日期载体做归一化。
- **None / 未配置供应商**：不读也不改 body/headers，不转换协议，原始 `fetch` 参数保持逐字节一致。

版本、证据等级（源码证据 / 兼容档案 / 实机抓包）见 [FINGERPRINT.md](FINGERPRINT.md)，测试矩阵与核对清单见 [VERIFICATION.md](VERIFICATION.md)。

## 为什么换协议也能在原聊天界面用

宿主在 `llm/stream` waterfall 里给出真实 provider/model/sessionId；插件用请求级 `AsyncLocalStorage` 绑定工厂创建与异步迭代（`next`/`return`/`throw`），在出站 `fetch` 上做头体变换，因此并发供应商、嵌套 None 请求不会串味。

原适配器的响应解析仍按原协议进行，插件负责把服务端 JSON/SSE 回译成原协议：文本增量、工具参数分片、用量、停止原因、取消都保留。只在工具定义 / tool choice / 调用与返回等结构位置映射工具名，用户文本和工具结果里的同名字符串不会被全局替换。

支持的原协议：Anthropic Messages、OpenAI Chat Completions、OpenAI Responses。只处理生成 POST 端点；模型发现、上传、OAuth 等外部 `fetch` 直接走原调用。没有无损表达的 hosted tools / 状态引用 / opaque reasoning 会在出站前返回结构化错误，而不是丢字段硬发。

## 缓存统计与前缀诊断

面板新增缓存观察区：默认显示最近 20 次完成的 HTTP 尝试，也可切换本次插件运行累计、最近活动会话，并按模型 / 客户端档案 / 协议筛选。命中率只使用上游明确返回读缓存字段的有效样本计算，缺失字段显示「未报告」，同时展示覆盖率、写缓存 tokens、首次观测、同轮多次 HTTP、失败、取消与未完成。

前台面板每 5 秒更新运行数据，保留未保存的配置草稿。0.4.2 将配置、运行概况与缓存统计整合为桌面单屏布局，移除了顶部重复摘要、运行周期信息、重置按钮、前缀诊断和出站监听区域。后端统计、内存诊断及原有 RPC 接口保留。

统计口径、字段覆盖、窗口边界和后端诊断细节见 [CACHE_DIAGNOSTICS.md](docs/CACHE_DIAGNOSTICS.md)。本次界面整合不改变请求头、系统模板、缓存保留时间、缓存断点或路由。

## 开发调试

后端保留进程内脱敏监听与 HMAC 诊断接口；主面板不再提供这些调试区域。监听默认关闭，不写磁盘；HMAC 诊断仅在内存保存有界指纹、结构长度和枚举，密钥每次加载随机生成。

## 工程结构

```text
src/index.ts             宿主生命周期、依赖注入、独立配置命名空间
src/core/                档案常量、日期归一化、工具映射、三协议请求转换
src/host/                配置/RPC、供应商发现、传输隔离、SSE/JSON 回译、监听
src/client/              侧边栏图标 + React 面板 + 纯状态模型（无宿主依赖）
profiles/                版本档案与来源摘要
scripts/build.mjs        TypeScript 编译 + 最小宿主 ESM 依赖集 + 浏览器单文件 bundle
cordis.patch.yml         可安装 bundle 的标准挂载配置
test/                    契约 / 集成 / 响应回译 / 真实 Cordis 运行时测试
```

仓库中的 `dist/` 用于 GitHub 直接安装，只保留宿主入口实际引用的 JavaScript 模块和 `dist/client.js` 浏览器 bundle。类型声明、Source Map 与客户端中间模块保留在本地 `build/`；每次构建会重新生成精简的 `dist/`，清除过期产物。源码、测试、锁文件、版本档案和第三方许可继续纳入版本控制，本地配置、调试记录及安装包由 `.gitignore` 排除。

## 测试

```bash
pnpm test          # 离线契约、用量解析、诊断与集成测试
pnpm run test:runtime  # 真实提取的 Cordis/DSH LLM 运行时兼容套件（10 项）
```

`test:runtime` 需要已提取的 DSH 运行目录，可用 `DSH_RUNTIME_MODULE_ROOT` 指定；它使用真实 Cordis/LLM 模块和本地响应，不发起真实上游模型调用。

离线测试同时加载实际发布的宿主入口，检查运行依赖完整、浏览器 bundle 可执行，并确认 `dist/` 不含孤立模块、重复客户端产物、声明文件或 Source Map。

## 常见问题

- **左侧栏没入口**：客户端半侧必须声明 `export const inject = ['slots']`（cordis 在未声明时读取 `ctx.slots` 会抛 `cannot get property "slots" without inject`，fiber 停在 loading，所有 slot 注册被静默丢弃）；确认插件已启用并刷新/重启。
- **供应商列表为空**：先到 DSH 模型设置注册供应商；面板只显示运行时已注册、可配置的第三方供应商。
- **不生效**：核对对话框选的供应商 ID、是否保存、是否选了 None；显示名称不是路由依据。
- **转换报错**：先给该供应商保存 None 恢复原请求，再看面板状态与脱敏监听定位。

停用/卸载会撤销 hook、恢复自有 `fetch` 包装并清空监听；官方供应商配置保持原样。本包无 postinstall，安装期不修改全局配置。

## 说明

本项目用于在自己的 DSH 上调整**出站请求的客户端身份字段**，便于使用只对官方 CLI 开放的第三方网关。上游网关的实际识别规则由其自行决定，本仓库的测试记录不等于任何第三方的验收结论。请只在你有权使用的供应商与账号上使用。

## 界面与品牌

设置面板采用 teal 品牌色与桌面双栏布局：左侧为供应商、客户端身份和并发配置，右侧集中展示运行状态与缓存统计。常用桌面尺寸中一屏显示完整内容；更窄窗口自动纵向排列，并保留内容溢出时的滚动访问。设置页中的嵌入面板使用设置页自身的滚动。

原创 M 形路径标记表达客户端身份切换，提供适合面板展示的彩色图标，以及随宿主前景色变化的侧栏单色版。

品牌图稿、接入方式与色值见 [BRAND.md](docs/BRAND.md)，SVG 源文件位于 `assets/`。
